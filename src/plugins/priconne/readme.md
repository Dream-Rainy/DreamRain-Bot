# priconne 公主连结 Re:Dive 插件

本插件整合了自动报刀（KCR 环奈连结R）、分刀、猜头像、猜角色、切噜语、arena 查作业等功能，已迁移为 NoneBot2 插件。

## 配置

环境变量（或 `bot.py` 所在目录的 `.env` 文件）：

- `priconne_arena_auth_key`：arena 查询 API 认证密钥（用于 bjjc/rjjc/tjjc 查作业）

群权限与 `chiffon_bot` 等相同，由 `permission_admin` 统一管理：默认全群可用，在群内使用 `perm off priconne` 可禁用本群（`perm list` 可查看本群是否可用）。

## 功能说明

### 1. 自动报刀（源自 KCR）

加机器人好友，私聊【绑定账号 账号 密码】

- 【出刀监控】【催刀】【当前战报】【我的战报】【今日/昨日战报】【出刀详情】等
- 【预约】【取消预约】【挂树】【下树】【sl】等

会长调度报表：

- 【今日刀表】（兼容【今日出刀】）：紧凑图片按3、2.5、2、1.5、1、0.5刀及暂无记录分组，仅展示刀数、成员标签和人数；重名附游戏ID。待核验成员仍按已有刀数归档，姓名后加`*`；刀型无法确定时，仅本图回退原始记录刀型，无可计数刀型时归0刀。异常及名册外成员仍单列。完整刀计1，尾刀和补偿各计0.5，分组不证明实际可用刀。期次、游戏日截止和必要提示收在图内。
- 【会战指挥台】（兼容【BOSS推进参考】【boss推进参考】，均返回同一张表）：每王一行，展示目标、状态与剩余 HP、现场队列、完整刀伤害参考、参考刀数、有效申报、申报缺口及调度提示。现场队列的“战/申/约/树”分别为实际挑战人数、申请数、当前/其他周目预约数和挂树数；成员登记明细另以纯文本发送。完整刀参考仅使用本期同王同阶段的伤害中位数及下四分位取值，“中/低”参考刀数分别按两者计算；不足 5 条记录或 2 名成员时不推算，不借用其他期样本。离线或活动结束时标明历史状态，不推算当前刀数或缺口。
- 【出刀时段】：使用保留的跨期历史战绩统计成员结算时段习惯，每两小时一档，每个游戏日每档最多计一次活跃。覆盖天数以成员有记录的游戏日为分母；不足 3 天显示样本不足，并列时段明确标记。报表标明实际样本日期，历史习惯不代表当前在线或有空。

结算与刀型口径：

- 按同一成员、同一期、05:00换日做默认配对：起始不足90秒为补偿；起始90秒且确认击杀时，默认普通尾刀，并按现有反秒公式计算延长时间；90秒满补优先配给之后最早的未击杀90秒战绩。该口径是推断：暂存满补先打整刀、用90秒补偿收尾可能误配。
- 刀型、击杀、延长时间分别记录。明确补偿刀或人工修正为补偿的记录，击杀后也不再延长。普通挑战超过每日3次、顺序或证据不足时显示待核验，不截断数字凑数；待核验不用于剩刀证明或完整刀样本。
- 【当前战报】按可核验的实际扣血计算伤害、分数和占比。历史重建须匹配当周目该王的服务器成员累计伤害；缺失部分注明未核验。其他报表、个人战报、KPI和刀伤参考继续使用原始结算刀伤。
- 击破播报格式：`成员对42周目1王造成100点伤害并击破（原始伤害500）。获得延长战斗时间90s。` 0秒时省略延长文本；无法推算时显示“延长战斗时间待核验”。
- 【修正出刀 编号 完整刀/尾刀/补偿】保存人工依据，后续重算保留；旧团队战工具修正也不再覆盖原始刀伤。
- 升级包含 Alembic 迁移 `c5e8b2d4a901`，在原战绩表增加可空的 `settlement` 字段。先按现有 ORM 迁移流程升级数据库后启动新版；旧记录原值保留，证据不足时不视为已确认刀型。

状态查询：

- 【状态】：蓝白状态图，查看监控人、活动进度、保存排名、五王血条、挑战人数、申请与挂树数量，以及状态刷新和战绩同步时间。监控人显示群昵称和QQ，昵称获取失败回退QQ；离线显示上次监控人，旧快照缺身份时显示未知。按当前情况给出最多两条操作提示，活动结束后引导查看复盘。
- 【boss状态】：同一状态图附申请、挂树明细及伤害申报有效性。现场人数未知时不按零人展示；离线、过期或活动结束时不读取现场登记。旧版快照保留进度原文，缺失字段不推测。

血条中位数M仅取本期同王同阶段的完整刀原始伤害，至少5条/2人。HP>3M为绿色健康；2M<HP≤3M为青绿至青蓝，提示准备合刀；M<HP≤2M为蓝色至蓝紫，提示建议合刀；HP=M为紫色收尾参考；0<HP<M为红色烂尾。血条长度按HP/总HP绘制。已击破、不可挑战、样本不足或状态/同步过期时使用灰色，不推测实时调度。

- 【预约表】：图片展示本期预约目标、成员、周目和留言；最新进度下标记已过周目的预约，旧进度只显示待核验。取消预约需带王号，如【取消预约 3】；管理员清空示例【清空预约 3】。
- 【查树】：图片按登记时间从久到近展示本期挂树成员、时长和留言，过滤上期及未来登记。登记数量不代表实际挑战人数；结算后使用【下树】清除登记。

预约表与查树每张最多两条操作提示。活动结束或尚未绑定本期时不读取旧登记；昵称查询失败显示QQ号。空表显示对应登记示例。
- 【自动报刀帮助】：按查看进度、出刀登记、战报复盘、监控管理分组，附常用参数示例。

会战复盘报表：

- 【会战复盘】或【会战总结】：发送本期总览、成员五日明细、分王表现、五王刀伤分布、成员刀伤分档共五张图。按本期05:00游戏日统计，末日23:59:59结束；保留无战绩的本期名册成员，不根据刀型次数认定漏刀。
- 【刀伤分布】：单独查看五王完整刀箱线图与散点，中位数、样本数和每次结算伤害同时展示。
- 【刀伤分档】：按成员在各王的完整刀伤中位数分成低于3亿、3～3.2亿、3.2～3.5亿、至少3.5亿四档（含下限、不含上限），列出成员与样本数。同一成员可在不同王属于不同档；单次样本仅供参考。

分布与分档使用本期有完整刀样本的最高阶段（D、C、B依次选择），不混合阶段或其他期。刀型使用默认配对及人工修正结果，待核验不混入完整刀样本；伤害保留原始值。每图标明战绩截止时间，无样本时明确显示。

当期开过监控的群会在第五天结束后的次日00:05（UTC+8）起自动收到这五张总结图，使用该群登记的机器人发送；`perm off priconne`禁用的群不发送。发送前尝试通过当前监控会话补采当期战绩；补采失败时明确标注仅展示已保存战绩。输入数据与逐页发送进度保存在该群数据目录的`summary_send.json`，失败每五分钟重试，重启后续发未成功的页，补发限结束后24小时内。手动查询不改变自动发送进度；超过窗口仍可手动查询本期复盘。

发送采用群接口成功后保存进度；若进程在接口成功与进度落盘之间中断，恢复时可能重复一页。新版仅为活动期间登记了期末总结收件信息的监控群自动发送，不补发早已结束的历史期次。

【出刀时段】另附“此时段可能活跃成员”：推荐只取本期前几个已完成游戏日的时段记录，分母为已完成活动日数，不含今天和其他期；同日同档重复结算只计一次。当前档至少在两个前日出现且仍有参考未完成量时列为联系线索；今日近 30 分钟有结算或有已关联身份的有效伤害申报也可列入。首日不借用跨期习惯推断本期偏好，记录频次不是在线概率。

【会战指挥台】附合刀候选与剩余时段联系规划。有效申报优先；未申报时，每人至少两条本期同王同阶段完整刀样本才给出历史联系候选及中位数量级，不计入有效申报，不推断击杀或补偿秒数。合刀候选成员不重复；历史候选只从当前联系时段选取。挂树、多王登记、申请与预约冲突或预约周目不明时先核验。状态或战绩同步超过两分钟、采集异常时不生成基于当前血量的申报组合；有人挑战或人数未知时不计算组合缺口，先协调结算。

时段规划每人只列一个联系窗口，按本期前日出现次数择优，并列优先较早；近期结算或有效申报优先当前窗口。参考未完成量冻结在生成时点，不证明有可用刀；已达三等效但有有效申报的成员仍列为待确认。剩余时段无样本或登记冲突的成员另列待核验，不猜测时段。普通游戏日规划至次日 05:00，第五天截断至 23:59:59；活动结束不安排出刀。缺少结构化 BOSS 状态时仍可展示历史联系候选，但不猜测当前血量或可挑战状态。

身份登记指令（仅公会群使用，无需账号密码）：

- 【登记会战成员 游戏ID】：把自己的 QQ 对应到当前群名册中的游戏 ID；一个 QQ 与一个游戏 ID 只能一对一登记，换 ID 前先取消。
- 【取消会战成员登记】：取消自己的对应关系。
- 群管理员可在上述指令后附加 `@成员` 代操作，例如【登记会战成员 1234567890123 @成员】。

对应关系保存在群数据目录的 `member_links.json`，不会被监控名册刷新覆盖。对应可保留跨期，但每期仅关联当前名册中仍在会的成员；不按昵称自动匹配。同名、改名、未登记或重复身份都不会自动关联错误战绩。未登记成员仍可作为历史联系候选，其申请、预约和挂树状态需人工核验；未关联身份的申报不参与人员组合与时段规划。

期次根据现有国服 wiki 日程库的会战 ID 和开战时间确定，活动持续五天，至第五天 23:59:59 结束；日程表的整月展示结束时间不作为出刀截止时间。每日额度为 3 刀，整期为 15 刀，累计应出为活动天数乘 3（上限 15），不根据首条战绩推算活动开始日期。活动结束后今日刀表不再显示当日出刀额度，累计战报仍显示该期已保存数据及“已结束”；下一期开战后自动切换。日程缺失时提示执行【更新wiki数据库】，不猜测期次。

除出刀时段习惯外，状态、指挥台、战报、KPI、出刀详情及编号修正均限定同一期。开启监控及监控运行期间切换期次时清理旧申请、预约和挂树登记；普通留言登记也需要处于活动时间内且已通过监控绑定本期。旧期次快照不作为新一期现场状态。历史战绩保留供出刀习惯统计，不再按 28 天自动删除。

成员伤害申报沿用【申请出刀】，示例（伤害支持整数万、w 或 W，补偿时长为 1–90 秒）：

```
申请出刀 3 完整 1000万 稳定轴
申请出刀 3 补偿60秒 450万 补刀轴
取消申请
```

申报需要最新会战状态，自动绑定该王的会战、周目及提交时血量；普通留言申请继续可用。同王重复申请更新伤害及登记时间，取消申请和 BOSS 击破继续清除登记。血量变化、换周目、换会战、超过 30 分钟、有挂树登记或同时对多王有效申报时不计入有效申报，需要重新申请确认；多王冲突先【取消申请】再确定目标。申报预计伤害应为该完整刀或该补偿时长内的伤害，不是剩余时间。申报伤害与参考刀数仅供调度，申报不证明仍有可用刀；实际可用刀、轴与伤害波动由会长确认。

报表采用 UTC+8 每天 05:00 换日，分别显示游戏状态刷新时间和战绩成功同步时间。成员名册在开启监控时刷新；超过 24 小时或更新时间未知会提示核验。采集异常和离线时仅展示已保存的数据，最近同步成功也不保证历史记录完整；已被旧版本清理的历史数据无法恢复。

维护命令：

- 【缓存运行群】：仅 SUPERUSER 可用，立即将当前监控与历史快照状态写入持久化文件。
- 【提醒掉线】：仅 SUPERUSER 可用，作为自动恢复失败后的人工兜底；只通知未恢复的监控群，并保留其最后一次历史快照。

监控发生临时网络异常或正在重连时会保留恢复信息；如果此时容器或进程重启，机器人启动后仍会尝试自动恢复监控。

## 数据目录

- 账号、会战、助战、分刀用户配置、设备 ID 等持久数据由 `nonebot_plugin_localstore` 接管，默认位于 `localstore` 的 `data/priconne/`
- 角色头像、arena 查询结果、识别库、作业网数据等可再生成缓存由 `nonebot_plugin_localstore` 接管，默认位于 `localstore` 的 `cache/priconne/`
