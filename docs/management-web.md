# 通用管理后台

后台沿用独立网页/中继：机器人只主动连接中继，不在机器人HTTP端口开放管理API。一个临时会话可进入别名工作台和已授权群的公会战页面。

## 启用

1. 初始化 `src/submodule/arcade-helper`，使用包含管理扩展的版本；机器人和独立中继都需更新。只更新机器人无法获得新页面。
2. 在独立服务器设置 `ARCADE_RELAY_TOKEN`（至少32位随机ASCII密钥）和 `MANAGEMENT_WEB_DOMAIN`，执行 `docker compose -f deploy/management-web/compose.yml up -d --build`。模板提供HTTPS，不连接机器人数据库。
3. 机器人配置：

```dotenv
management_web_enabled=true
management_web_relay_url=https://管理域名
management_web_relay_token=与ARCADE_RELAY_TOKEN相同的服务密钥
```

默认不开启新管理入口；`alias_web_enabled` 控制别名网页功能（包括后台别名模块），`alias_web_relay_url` 和 `alias_web_relay_token` 继续配置原别名专用入口。两个入口可指向同一个管理中继，旧 `/arcade.editor` 链接继续使用。

本地开发可先执行 `uv run python scripts/management_relay.py`，将地址设置为 `http://127.0.0.1:8765`；公网必须使用HTTPS。前端无CDN和构建步骤。

## 登录与权限

私聊机器人发送【管理后台 [群号]】，打开临时链接。链接最长一小时，等同创建者的临时凭证，请勿转发。浏览器读取fragment后立即清除地址栏密钥；刷新、断线、退出或任一端重启后需重新获取链接。不要将链接写进访问日志或截图。

- 普通成员：经机器人核验所在群后，可以查看该群会战数据；可以使用原别名提交功能。
- 群管理员/群主：可以修改本群普通播报和档线订阅开关，不因此获得别名审核权限。
- 超级用户：可以访问经核验机器人所在的群；别名审核仍使用 `SUPERUSERS` 和原来的禁止自审规则。

指定群号的链接仅授权该群；切换其他群需重新获取链接。不带群号的链接可在页面选择群，但每次请求仍检查成员身份。首批群角色校验支持OneBot V11，无法核验的适配器或请求不会放行。插件群/用户禁用、全局黑名单也作用于后台；角色撤销后无法继续写入。

## 同域页面入口

同一个管理中继提供以下路径，域名只需统一反向代理到该服务：

| 路径 | 页面 | 私聊指令 |
|---|---|---|
| `/manage/` | 统一后台，默认选择可访问模块 | 【管理后台】 |
| `/manage/clanbattle/` | 公会战 | 【管理后台 公会战 [群号]】或【管理后台 群号】 |
| `/manage/aliases/` | 统一后台内的别名审批 | 【管理后台 别名】 |
| `/arcade/aliases/` | 原独立别名工作台 | 原 `/arcade.editor` |

模块导航同步更新URL，浏览器前进/后退在当前页面内切换模块，保持同一加密连接。公会战的报表子标签仍在页内切换。URL只选择展示模块，访问范围和操作权限由后端核验；无权访问的模块不会自动转入其他业务。

稳定路径不包含登录凭据。直接打开无凭据地址、刷新或在新页面打开已清理的地址，仍需从机器人获取新的临时链接。临时凭据读取后清除，不进入导航历史或网页缓存；本功能不提供持久登录。

## 公会战

提供状态、今日出刀、成员五日矩阵、刀伤分档、申请/预约/挂树队列和补偿库存。仅读取现有采集数据，不因打开页面登录游戏或触发补采。显示刷新、同步时间和待核验状态；旧快照不作为现场状态，登记人数不作为实际挑战人数。

统计与QQ共用：05:00换日、第五天23:59:59截止；今日和五日保留折算/星号规则；刀伤分档按起始90秒且实际打满90秒筛选，使用原始刀伤；补偿保守求解并显示范围。大整数不交给浏览器作隐式数值转换。

短时间切回已访问的报表或成员列表时，页面可先显示“上次结果 · 刷新中”，随后读取最新数据。旧结果下管理按钮不可用；刷新失败会保留提示，不能据此执行修改。设置、记录详情和纠正预览/保存始终重新请求，不使用页面结果缓存；保存成功后相关缓存清除。页面缓存仅保留在当前临时会话内，到换日、活动截止、退出或断线时失效。

管理员可修改普通播报和期末档线订阅。页面携带读取时的旧设置，遇到其他入口修改会要求刷新。保存失败不更新内存，超时后先刷新核对，不自动重放。后台不开放游戏密码、任意命令或清空群数据；刀型纠正在下述记录管理页单独处理。

## 接入模块

模块向 `src.plugins.management.portal` 的 `Portal.register()` 注册 `Module(id, title, plugin, dispatch, authorize)`。`authorize(identity)` 和 `dispatch(identity, method, path, query, body)` 是异步函数，身份由可信机器人事件建立，不接受浏览器指定actor。`dispatch`必须逐项核验资源范围、方法和输入；不可把RPC转成任意URL/命令调用。模块自己的领域用户ID由服务端换取。

通用入口只提供me/modules/logout及已注册模块分发，路由只在进程内部ASGI应用中运行。返回分页JSON，单条业务结果上限480000字节；模块提供自己的前端面板，后台不自动生成数据库管理页面。别名面板复用 `mountAliasPortal(root, relay, onLogout)`。

`EditorBridge.open(page_path=None, **identity)`可为单次临时链接选择同源页面入口；省略时使用构造器默认入口。它不改变身份或模块授权，也不会修改其他会话的入口。

会话和中继均使用单进程、内存存储；部署多个worker前需先引入共享会话机制。中继负责提供页面和加密帧转发，不保存明文业务数据；网页资源和中继本身仍需可信部署。

## 人员管理

【人员管理】按姓名、游戏ID、QQ、关联状态筛选本期成员，显示今日参考折算、补偿库存及登记。游戏名册由游戏采集；关联失效或冲突会保留展示，不能用于调度。普通成员可关联/解绑自己，管理员可代操作，其他QQ须经群成员核验，不能重复占用游戏ID或静默改绑。关联文件异常时不覆盖已有登记。

管理员可确认清理本期单条预约、申请或挂树。页面提交条目版本及期次；登记、名册或期次发生变化需刷新，不会将旧页面操作套到新登记。

## 出刀纠正

【出刀纠正】提供成员、活动日、王号、刀型与待核验筛选。详情分别显示原始刀伤/标记、采集时长、推断结果、有效扣血、人工覆盖、补偿来源和最近20条修正历史。原始字段只读，不补造战绩。

群管理员/超级用户可修正为完整刀、尾刀、补偿刀，或撤销人工修正。补偿来源按数据库记录ID指定，须为同成员、同一期、同游戏日更早的可用来源；不能重复消费，90秒满补也由整日约束验证。秒数和采集覆盖不足时仍保留待核验，不把人工指定解释为已经确认实际库存。

填写原因后先【预览整日影响】，核对相关刀型、参考折算和补偿库存，再【确认保存】。影响判断的采集变化或他人修正会使预览失效，须重新预览；仅刷新成功时间推进不会要求重做。改变刀型/来源/理由后也需重新预览。新增人工约束与已知事实冲突会拒绝保存；撤销覆盖可以恢复到仍待核验的自动结果。保存和撤销均在事务内记录操作者、时间、原因、前后值及修订号。后续采集不会覆盖修正，也不会复活已经撤销的旧覆盖。

QQ群【修正出刀 编号 完整刀/尾刀/补偿】同样要求管理员或超级用户，记录操作者并共用校验。编号匹配多条记录时拒绝批量修改，请在后台按稳定记录ID核对；后台提供预览和撤销。
